# 方案定稿：PDF 页边批注

- 日期：2026-09-22
- 状态：**已实施，收尾验收中**（主体见 `3ef1be0`…`f797b2b`；2026-09-24 按「仿 Word」把卡片排法改为贴行，见 §1.3）
- 定位：PDF 原版式上的批注模块。对标当前 Word（Microsoft 365，本机 Word 16.0.20326）：选区是落点，页边有气泡，页面右侧的批注栏里，卡片与所批注的那一行对齐。高亮和下划线仍是日常标记，不靠这个模块才能用。
- 关联：取代 [`plan-annotation-system-redesign.md`](./plan-annotation-system-redesign.md) 里「一条摘录至多一条感悟、不提前引入评论线程」对 **PDF** 的约束。Markdown / EPUB 的感悟、间隔回顾、全库标注中心这一轮不动。

> 一句话：阅读设置里一个默认关闭的开关。打开后，在 PDF 原版式对选区批注；保存后页边出现气泡，右栏里的卡片贴着那一行。关掉开关，批注界面像不存在，高亮、下划线和阅读位置照常。只有单独确认的「清空 PDF 批注」才删数据。

---

## 1. 已定行为

这些决定来自 2026-09-22 的 grill，不再在实现时重开。

### 1.1 开关

- 全局一个，放在现有「阅读设置」里，默认关。
- 关：页右栏、页边气泡、选区工具条上的「批注」、本文标注里的「讨论」列表一起消失。页面把右栏占的宽度让回去。未保存的草稿丢掉，不补高亮、不建讨论。
- 关的时候仍可用：三色高亮、下划线、本文标注的「按页」、阅读位置。
- 开，但本文还没有任何讨论：右栏不占位。
- 开，且已有讨论：单页和双页都显示右栏。
- 只在 PDF **原版式**出现。阅读模式没有批注按钮、气泡和右栏。

### 1.2 怎么写

- 选中文字，在选区工具条点「批注」，就地写完再保存。保存之后右栏和气泡才出现。
- 保存后不自动把侧栏切到「讨论」。
- 选区上已有高亮或下划线：挂到重叠最多的那一条，不改颜色和线型。再写一次是这串里的回复，不新开一串。重叠一样多时，取文档顺序里更靠前的那条。
- 选区上没有标记：补一条高亮，颜色用最近一次高亮色；从未用过则用现有默认高亮色。样式是高亮，不是下划线。
- 每条标注仍只落在一页。划选跨过页边界时按页拆开：高亮和下划线每页各存一条（颜色相同，一次撤销整组撤掉）；批注的讨论挂在选区起始页那一段，后面几页补上普通高亮，不带讨论。一次最多拆 10 页。
- 作者只有本地的一个署名，默认「我」，可在阅读设置里改名。卡片头像取这个名字的首字。不提供多个身份。

### 1.3 右栏和页边

- 卡片与 Word 一样贴行：每张卡片的顶边对齐所批注选区的第一行。几张卡片挤在一起时，按页码、页内从上到下的顺序依次往下让，保持固定间距，不互相遮挡。（2026-09-24 改定，取代原先「从栏顶依次堆叠」。）
- 批注栏是固定的界面尺寸，不随页面缩放：卡片宽 264px，正文 13px。居中的是页面本身，批注栏挂在页面右侧的留白里；留白不够时页面只往左让出缺的那一段，再不够才横向滚动。适宽时页面填满批注栏留下的宽度，不为居中再缩小。（2026-10-07 改定，取代原先「页面和批注栏作为一整条一起缩放、一起居中」。）
- 批注栏跟页面一起滚动，不单独滚动；在栏上滚轮等同于滚正文。最后一张卡片超出最后一页时，页面底部补出空白，保证能滚到它。
- 只有当前卡片展开回复、修改、删除。其余卡片只显示内容。当前卡片对应的高亮加深。
- 页边气泡不是头像。它粘在那一页的选区旁，缩放和双页时跟着那一页走。点气泡或卡片只选中该讨论，不滚动正文。点正文空白处取消选中。
- 点讨论目录的一行，正文滚到那处选区，并选中那张卡片。
- 本文标注的「讨论」是目录：一行一条，页码加第一句。点一行，效果与点右栏卡片相同。完整卡片只放在页右栏。
- 本文标注的搜索包含讨论正文。命中后走讨论目录那一行。

### 1.4 删除

- 删一条回复不再确认。最后一条删掉后，这串讨论消失。若高亮是批注时自动补的，连那条高亮一起去掉。手动画的高亮和下划线只删讨论，标记留着。
- 「清空 PDF 批注」在阅读设置里，和隐藏开关分开，必须再确认一次。删掉全部 PDF 讨论，以及当初只为批注自动补上的高亮。手动标记不动。
- 代码不再挂载这个模块时，不自动删库。

### 1.5 数据

- 讨论留在现有用户库。备份和恢复沿用现有用户库备份。这一轮不新做可读文本导出。
- 已迁进讨论的 PDF 旧感悟继续当讨论用。开关默认关，所以打开 PDF 时先看不见，直到用户打开开关。数据还在。

## 2. 这一轮不做

- 不把批注挂到 Markdown / EPUB。那两种格式的感悟先留着，以后再迁。
- 不拆间隔回顾，不拆全库标注中心。批注模块不调用它们。
- 不改阅读位置。
- PDF 上不再提供单独的「写感悟」。PDF 旧感悟已经进讨论。
- 不做嵌套回复、@、解决线程、多人身份、墨迹、语音。
- 阅读模式不批注。
- 不新增快捷键。入口是选区工具条上的「批注」。
- 不因为实现方便去改高亮的三色或下划线语义。

## 3. 实施对照

2026-09-22 起在 `feat/标注功能` 分支落地。下表是每条方案对应的实现，后续改动以代码和测试为准。

| 方案 | 实现 |
| --- | --- |
| 开关，默认关 | `readerPreferences.pdfCommentsEnabled`，阅读设置「PDF 批注」 |
| 表与迁移 | schema 8：`comment_authors`、`pdf_comment_threads`（含 `anchor_created`）、`pdf_comment_messages`；PDF 旧感悟迁成第一条讨论 |
| 写、回复、改、删、清空 | `create_pdf_comment_thread`、`reply_to_pdf_comment`、`update_pdf_comment_message`、`delete_pdf_comment_message`、`clear_pdf_comments` |
| 挂到重叠最多的标记，否则补高亮 | `src/lib/comments/commentPlacement.ts` 的 `commentTargetForSelection`；`App.tsx` 的 `commitPdfComment` |
| 卡片贴行、不重叠 | `commentRailLayout.ts` 的 `layoutCommentCards`，`PdfCommentRail` 用实际高亮位置测量 |
| 有讨论才留栏，适宽让出栏宽 | `PdfReader` 的 `hasPdfComments` 与 `commentFitNativeWidth` |
| 页边气泡 | `PdfPage` 的 `commentBubbles` |
| 讨论目录与搜索 | `DocumentAnnotationsView` 的「讨论」页；`sync_comments_to_excerpt_search` |

用户库已被开发版写成 schema 8。已安装的 schema 7 正式版打不开这个库。这是现状，不是这一轮要额外解决的发布问题。

## 4. 模块边界

批注是一块可以挂上、也可以卸下的模块。卸下指构建时不再挂载界面和命令；那不等于清空。清空只有 §1.4 那个确认动作。

**模块拥有**

- 讨论串、回复、作者「我」、页右栏、页边气泡、选区上的批注入口、本文标注里的讨论目录。
- 用户库里的三张批注表，以及改、删、清空这些命令。
- 「这条高亮是不是批注自动补的」这个标记，用来在删光讨论或清空时决定高亮去留。

**阅读器提供**

- 当前 PDF 文档、同一页内的选区、选区在页面上的矩形。
- 缩放、双页、滚动。右栏出现或消失时，若当前缩放仍是适宽，按栏左侧的剩余宽度重新适宽；用户手动缩放过则不改缩放，页面在左栏里滚动，不盖住右栏。

**不拥有**

- 三色高亮、下划线、按页列表、阅读位置、间隔回顾、全库标注中心。

挂载点保持少而固定：PDF 原版式一个栏位、选区工具条一个动作、本文标注一个目录页、阅读设置两个动作（显示 / 清空）。模块的类型、布局和界面放在现有 `src/lib/comments/` 与 `src/components/comments/`，不要再散进摘录包的新概念里。持久化仍在用户库，但命令和「自动高亮」规则归模块，不把讨论字段继续摊进无关的回顾逻辑。

## 5. 收尾

1-5 步（开关、右栏与气泡、写入路径、改删清空、模块收口）已落地。剩下：

- 选区高亮同一行拼成一条，开着批注栏横向滚动时工具栏保持居中。
- 在真实窗口里按 §6 走一遍，明暗主题、窄窗口、双页都要看。

## 6. 验收

- 默认打开一份已有讨论的 PDF：看不到右栏、气泡和「批注」，高亮仍在，页面不被栏挤窄。
- 打开开关后，讨论按页码和页内位置排在右栏；双页也在；气泡跟着对应那一页。
- 对没有标记的选区批注：保存后出现一条最近高亮色的高亮、一个气泡、一张卡。侧栏仍停在原来的页。
- 对已有下划线或高亮再批注：线型和颜色不变，新内容是回复。
- 删到最后一条：讨论消失；自动高亮消失；手动画的标记还在。
- 阅读设置里清空：确认后全部 PDF 讨论和自动高亮消失；手动标记还在。只关开关不会清空。
- 阅读模式、Markdown、EPUB 没有这套批注界面。
- 按 [Agent 参考](./agent-reference.md) 的「新功能的真人交互验收」，用 computer use 在桌面开发窗口里把上面各条点一遍。测试通过不等于本方案已验收。
