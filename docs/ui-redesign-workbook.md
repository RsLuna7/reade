# Reade 整体 UI 设计工作册

状态：第 1 步，全局盘点与使用场景确认。尚未确定整体新布局，未开始产品代码改版。

## 协作方式

- 每轮解决一个会影响设计的主要问题，用户参与使用优先级、方案选择和体验评价。
- Agent 先解释判断依据、给出推荐及取舍，再请求意见；已确认的事项不重复询问。
- 技术实现细节由 Agent 处理；涉及功能隐藏、入口迁移、信息密度或明显改变习惯时，提交具体方案供用户选择。
- 先形成产品与整体界面的共同依据，再分区域实施。局部方案不能自行覆盖全局规则。

## 已确认事项

1. 本地 Windows 阅读器；桌面为设计对象，现有 Web 版冻结功能。
2. 目标是减少重复描边与组件拼装感，改善流畅、舒服的交互。
3. 保留纸感和 Reade 品牌识别度，优先使用现有技术与主题体系。
4. 侧栏估计阅读时长保留，用户把它视为书本长度指标，而非选书决策依据。
5. 侧栏局部方向已接受：标题最多两行、时长下移说明行、同类文档行高一致。
6. 用户希望参与整体设计，逐步讨论后推进。
7. 第一优先使用路径已确认：长时间读一本书，偶尔查目录、调设置。以持续阅读的舒适与连续性安排首轮设计验证。
8. 用户确认阅读过程中需要左侧书库一直显示；标准桌面阅读布局保留常驻书库，不默认收起或悬停唤出。窄窗口沿用现有适配，后续单独验证。
9. 用户确认右侧章节目录也一直显示；标准桌面采用左侧书库、中央正文、右侧目录三栏常驻。保留右栏现有目录／标注切换，不将目录默认隐藏以追求沉浸感。

《plan-sidebar-refinement.md》保留为侧栏子方案。具体字号、行高、底栏位置和菜单参数仍需完整窗口原型验证，不当作全局设计系统的既定参数。

## 2. 使用路径与优先级

### A. 持续阅读

用户已选为第一优先路径。

打开书库 → 进入一本书 → 持续阅读 → 偶尔查目录或调整设置 → 继续原位置。

需要验证：正文可用空间、工具显露方式、设置反馈、目录跟随、返回后位置稳定。

### B. 查阅与多文档切换

打开书库 → 辨认／搜索教材 → 跳到目标内容 → 切换另一份材料或分栏 → 回到之前的位置。

需要验证：长标题辨认、搜索结果定位、回退路径、导航密度和快捷键效率。

### C. 标注与整理

阅读 → 划选与标注 → 查看当前书摘录 → 全库整理或回顾 → 返回原文。

需要验证：标注入口与选区浮层关系、工具状态、原文跳转、二级页面返回和上下文保留。

三条路径均保留功能；选择优先路径只决定设计时的注意力分配与第一轮原型场景。

## 3. 需要先统一的共享规则

| 规则族 | 应一起检查的区域 | 忽略时的风险 |
| --- | --- | --- |
| 文字与颜色角色 | 侧栏、顶部、目录、设置、统计 | 相同角色不同清晰度，局部调色波及全局 |
| 按钮与状态 | 全局图标按钮、PDF 工具、标注工具 | 同类操作出现不同触感、选中与悬停混淆 |
| 导航与切换 | 列表／书架、目录／标注、主页／阅读 | 切换样式或返回预期不一致 |
| 浮层与焦点 | 切库、设置、右键、提示、标注、对话框 | 动效、关闭时机、遮挡与焦点返回不一致 |
| 空间与响应式 | 三栏、分栏、工具栏、抽屉 | 单区变宽导致正文和其他控件受挤压 |
| 动效策略 | 所有高频操作及临时浮层 | 有的瞬间跳变、有的拖慢操作；减少动效设置不一致 |
| 加载与错误 | 文档打开、搜索、合集、导出 | 用户不知道是否成功，或恢复时丢失阅读位置 |

这些是共同的设计任务，不意味着本轮先抽象或重写所有基础组件。
