# Reade 缺陷审计与修复记录（2026-08-30）

## 结论

本轮在当前工作树上确认了两类缺陷：

1. 当前工作树已有的冷启动首篇读取失败无限重试问题，现有修复及回归测试已验证通过。
2. 新发现并修复了跨书库异步竞态：书库 A 的文档读取、搜索结果或错误可能在切换到书库 B 后回写，污染 B 的状态。

本轮自动化验证全部通过；共享阅读界面在明色、暗色和接近桌面最小宽度的浏览器冒烟中未发现控制台错误或可见布局破损。一次审计不能证明项目不存在其他缺陷，未覆盖项见文末。

## 缺陷与证据

### B-001：旧书库的异步结果污染新书库

- 影响：切换书库时，如果旧书库的 `readDocument` 或 `searchDocuments` 较晚返回，新书库可能显示旧文档、旧搜索结果或旧错误提示。
- 根因：动作只用同类请求序号过滤乱序响应，没有校验响应所属的书库上下文。
- 复现证据：先补回归测试，修复前定向运行稳定出现 2 个失败：`currentPath` 收到 `old.md`，`searchResults` 收到旧书库结果。
- 修复：在成功提交新书库时递增 `activeLibraryGeneration`；文档读取与搜索在发起时捕获世代号，成功和失败回写前同时核对请求序号与世代号。普通 `refreshLibrary` 不递增世代，避免误取消仍属于同一书库的请求。
- 回归覆盖：旧文档结果、旧搜索结果、旧文档/搜索错误三条场景。

### B-002：冷启动首篇读取失败后无限自动重试

- 影响：首篇文档无法读取时，`currentPath` 保持空值且 `loading` 翻转，自动打开 effect 会持续重跑，造成加载遮罩闪烁和重复读取。
- 状态：本轮开始时工作树中已存在修复和测试；本轮没有改写该实现，仅审查并通过全量验证。
- 现有修复：同一书库快照、同一路径只自动尝试一次；新快照允许重新尝试。

## 未修复警告与未覆盖范围

- 生产构建仍提示 `coverCapture.ts` 同时被静态和动态导入，动态导入不会形成独立 chunk；同时存在大于 500 kB 的 chunk。这是既有性能债，未观察到功能错误，本轮不做无关拆包重构。
- Vite 开发服务器在相关模块 HMR 时提示 `AnnotationUi.tsx` 的 `annotationSupportsCard` 导出与 Fast Refresh 不兼容；会退化为模块失效/重载，未影响生产构建或最终用户运行。本轮未做无关模块拆分。
- 未在真实 Tauri/WebView2 窗口中手工执行书库 A→B 的慢 I/O 切换；竞态由可控 Promise 单测稳定复现并验证。浏览器冒烟只覆盖共享界面，不等价于完整桌面 IPC 验收。
- 未做真实 PDF/EPUB 大文件、文件 watcher、安装包、系统文件对话框和长时间压力测试。
- Web 版已封存，本轮只用它做共享 UI 冒烟，没有新增或验收 Web 功能。
