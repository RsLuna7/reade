# 创新功能路线图

- 日期：2026-08-13
- 定位：上一阶段六项功能（双链/合集/金句卡片/朗读/相关段落/分栏）落地后的下一轮创新清单。23 个功能分 9 批推进，每个功能独立可回退。
- 基线：提交 `e612720`（上一阶段功能基线）。此后每个功能一个 `feat:` 提交。

## 提交与回退约定

- **每功能一个提交**：一个功能 = 一份 `docs/plan-*.md` 方案 + 实现 + 测试 + 一个独立 `feat:` 提交（方案文档随该提交或紧邻提交入库）。
- **撤销单个功能**：`git revert <sha>`（生成反向提交，历史保留）。
- **整体回到某版本**：`git reset --hard <sha>`（丢弃其后全部改动，慎用）。
- **查版本**：`git log --oneline` 找到目标 sha。
- 状态列取值：未开始 / 草案进行中 / 草案 / 定稿 / 已实施。

批次 7 备注（缓存 schema 协调）：书架封面缩略图表 `document_thumbnails` 以 `CREATE TABLE IF NOT EXISTS` 纯附加进缓存 sqlite（`document_links` 先例），**未 bump `CACHE_SCHEMA_VERSION`**——纯新增表不触发整库删除重建，万篇库免于一次全量重索引；因此批次 9「增量重读」的文本快照表也无需本批预建，若届时确需 bump 再一次建齐两表（见 `docs/plan-bookshelf-covers.md` §0）。

除批次 1 外，各功能的方案草案由并行工作流产出（状态列为"草案"）；实施前须先定稿方案。所有功能沿用既有硬约束：零新依赖、离线只读、不放宽 CSP/capability/路径校验、纯逻辑进 `src/lib/`、共享状态进 Zustand store、桌面与 Web 同一套 UI。
